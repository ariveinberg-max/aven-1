# Week 3 retrospective (Phase 1's first week)

## Shipped

- Fixed a real, long-standing bug: `raft.py`'s own candidate-generation temperature schedule never received the diversity fix `server.py` got weeks earlier. Measured fix: average candidate spread 1.726 → 6.949.
- Ran a third reward-model + RAFT cycle (79.63% held-out, up from 60.53%) and promoted it (RAFT-3) after a clean live-check and 0 regressions.
- Retrained KTO and finally did the live-inspection that had been an open item since Day 10 — found a real generation glitch the frozen suite missed. Not promoted, but the open item is closed.
- Retrained DPO on the full current dataset (587 comparisons, up from 112) — genuinely clean result, correctly not promoted since it wasn't demonstrably better than what's already live.
- Ran PPO a third time at the largest data scale yet (252 comparisons) and formally concluded it: three attempts, three scales, four coefficients, never a clean result. This is now a real, documented finding, not an open question.
- Second GPU acquired ($126, NVIDIA) and made operational; measured Aven-2's first-ever real throughput number (2,289 tokens/sec) directly from training logs, not estimated.
- Diagnosed why the frozen capability suite keeps missing real regressions: zero conversational-prompt coverage, by construction. Concrete fix proposed (not yet built).
- Quantified something this project had been calling "noisy" without ever measuring it: reward-model retrain accuracy swings are within statistical noise for a validation set this small, not real model change.
- Published 8 build-log entries (5 through 12) and kept the public roadmap artifact honestly up to date multiple times as real state changed (hardware, PPO's conclusion, the labeling-bottleneck rules, two new milestones).
- Preference dataset grew from ~974 to 1,251 comparisons.

## Failed (found and reported honestly, not smoothed over)

- Three separate, real attempts at fixing the labeling-prompt-pool bottleneck — a dictionary-based coherence filter, an adaptive-temperature schedule, and an LLM-judge coherence check — all failed to reliably catch the actual defect pattern observed live. Each is logged with why, not deleted or hidden.
- A promising early result (preference-strength filtering: +10 points) did NOT replicate on a second seed (-12.9 points) — caught before it was reported as a real finding, which is the discipline actually working as intended, not a failure of the idea alone.
- Lost the planned AMD-vs-NVIDIA throughput comparison entirely — the AMD card is no longer owned, and no baseline was ever recorded before it left. Reported as a standalone number instead of a fabricated comparison.
- The GitHub Student Developer Pack application was rejected once (billing-name mismatch), then hit a second dead end (school email verification blocked by district IT, unfixable from this side). Fixed the first, worked around the second, resubmitted.
- One real overcorrection: auto-checking Phase 0's roadmap checkboxes by default was the wrong call and got reverted the same day it was tried.

## Remains open

- The core labeling-bottleneck problem is still unsolved after three real attempts. The direction has shifted from "detect/filter garbled generations" to "run fewer, more conservative RAFT cycles" — a real, measured finding (RAFT-2 ties less than RAFT-3 on identical prompts) with a published mechanism behind it, but not yet acted on.
- SSH access to the Windows PC is still not working — blocks independent verification of anything there, and blocks the newly-added Day 25/30 roadmap milestones (SSH fix, then corpus expansion).
- The Aven-2 parameter-count discrepancy (155M vs. 153M, open since Day 3) is still unresolved, waiting on that same SSH access.
- Whether repeated DPO/KTO rounds show the same compounding collapse RAFT does is a real, testable, currently-untested hypothesis.
- The reward model's validation set (currently ~70-90 examples) is still too small for confident single-run comparisons — a fixed 200+ example held-out set has been recommended twice now but not built.
- `checkpoints-pre-raft3-2026-09-13-backup` can be retired once RAFT-3's stability is confirmed across more sessions, matching this project's own established rule.
