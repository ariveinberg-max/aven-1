Closing out Day 15: a DPO retrain that came back clean but stayed on the bench, and a statistical finding that reframes a pattern this project has been reporting as a mystery for a week.

## DPO retrained — clean, but not a reason to switch
DPO hadn't been touched since Day 8, when it ran on just 112 comparisons. Retrained it on the current 587-comparison pool (236 usable train pairs, more than double): held-out accuracy landed at 82.14%, noisier step-to-step than Day 8's clean convergence but higher and far more stable than KTO's same-day 0–100% swings.

Live-checked 10 prompts against the currently active checkpoint: 9/10 identical, the 1 change was a harmless equivalent phrasing, not a defect. Frozen suite: 0 regressions. This is a different kind of result than PPO or KTO's failures — DPO didn't hide a problem behind a good-looking metric, it just didn't demonstrably beat what's already live. Not promoted, kept on the bench as a real, current fallback if RAFT's reward-model dependency ever becomes the actual bottleneck.

## The reward model's "noise" was never actually measured
Since Day 8, every retrain's held-out accuracy has bounced — 76%, 75%, 60.53%, 79.63% — and every entry describing it used the word "noisy" without ever checking what that word should mean statistically.

Did the math today. A held-out accuracy on a validation set this small (24–54 examples) carries a 95% confidence interval of roughly ±11 to ±17 percentage points. Every one of the four measured intervals overlaps at least one neighbor. The entire observed spread — which reads in a training log like the model getting dramatically better or worse — is fully explainable by ordinary sampling noise on a validation set this size. A single flipped example alone moves the reported number by 2.6 to 4.2 points at these sample sizes.

Found a second, compounding issue while checking this: the validation set isn't even the same data across retrains — it's resampled from a growing pool each time, so even a perfectly stable reward model would show apparent swings just from evaluating on a different sample. Practical takeaway going forward: report a confidence interval alongside any held-out accuracy from here on, or move to a fixed, never-retrained-on validation set once the labeled pool is large enough to afford one (200+ held-out examples would tighten the interval to roughly ±6–7 points) — that's the only way cross-retrain comparisons on this metric become actually meaningful.
