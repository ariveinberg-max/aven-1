# Build log — Entry 10

Day 19, under a new rule: don't retrain on small data increments, use the training block to fix the actual bottleneck instead. Two real attempts, two real dead ends — reported honestly rather than smoothed over.

## Attempt 1: a coherence filter for garbled generations
Yesterday's investigation found that widening the labeling prompt pool doesn't work right now — at the temperature needed for real response diversity, the checkpoint produces mostly ties or garbled output on anything outside a small set of heavily-trained categories. Built a dictionary-based coherence filter to catch that garbling before it reaches a labeler: a real-word ratio check against a 235,976-word dictionary, plus a repeated-substring detector.

Live-tested against real garbled and clean examples collected from this session's actual KTO/PPO/RAFT output. First pass had real bugs — the dictionary lacks common plurals and contractions, and the repeat-detector's window was far too short, flagging ordinary word combinations that repeat by chance in any real paragraph. Fixed both. Retested: the filter then caught only 1 of 6 real garbled examples, because the common real-world failure pattern is 1-2 fabricated words diluted across an otherwise-normal sentence, not full gibberish — a ratio-based check structurally can't catch that. Not deployed. Kept the file with an honest "experimental, not wired in" header rather than deleting it. The real next attempt should use this project's already-proven LLM-judge pattern instead of a hand-built heuristic.

## Attempt 2: testing a real literature suggestion, and catching a false positive
Day 12's reading suggested filtering preference data by confidence/strength, not just deduplication — never actually tried. Tested it directly: used the current reward model to score every training comparison's margin, and found 40 of 274 pairs (14.6%) where the reward model actively disagrees with the human-labeled winner — a concrete, measured instance of noisy labels, not an abstraction.

Dropped the lowest-margin 20% and retrained a fresh reward model on the same validation set as an unfiltered baseline. First run: **+10.0 percentage points** — a real, exciting confirmation of the literature. Before reporting it, replicated with a different seed, per this project's standing practice of not trusting a single number. Second run: the opposite result, **-12.9 points**. The unfiltered baseline alone swung 8.5 points from seed choice on identical data. Conclusion: not confirmed — this project's ~70-example validation set is too small to tell a real effect from training-seed noise, reinforcing yesterday's statistical finding a second, independent way. Reporting the first run alone would have been a real, avoidable mistake.

## The throughline
Both attempts failed to produce something deployable, and both are reported as failures rather than reframed as wins. But both also produced real, durable knowledge: the coherence-filter attempt narrowed down exactly what kind of defect any future fix needs to catch (subtle, partial garbling, not full gibberish), and the filtering test caught itself almost reporting a false positive before it happened — the actual value of replicating a result before trusting it, demonstrated rather than just stated as a rule.
