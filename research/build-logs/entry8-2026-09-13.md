# Build log — Entry 8

The planned tokens/sec comparison, and an honest reason it can't be a comparison anymore.

## Measuring real throughput on the new GPU
Got two real readings from Aven-2's own `status.json` on the Windows PC, 421.4 seconds apart: step 40,311 → 40,939 (628 steps), batch size 8, context 192. That's **1.49 steps/sec → 2,289 tokens/sec** — computed directly from `train.py`'s own tracked step and elapsed-time fields, not estimated or pulled from a dashboard.

## Why there's no AMD number to put next to it
The roadmap's original task was to measure this against "the AMD device's recorded baseline." That baseline never existed. Checked directly: `train.py` computes tokens/sec internally but only logs it to W&B, never to the console; and Aven-2's AMD/DirectML training runs were always local, offline W&B runs that were never synced to the cloud project. There was nothing to look up.

The plan was to get a real number anyway — benchmark the AMD card directly, same two-reading method, right now. That's no longer possible: the AMD RX 5500 XT is no longer part of the setup. So this entry reports one real, verified number rather than a comparison, and says so plainly instead of quietly dropping the "vs. baseline" framing or reconstructing a number that was never measured.

## What this number is for going forward
2,289 tokens/sec is now Aven-2's own baseline — the first real throughput figure ever recorded for this project's actual training hardware. It won't answer "was the new GPU faster than the old one," but it will answer "did the next hardware or config change actually help," which is the same kind of measurement discipline this project has applied to every model result so far: report what was actually measured, not what would have been convenient to measure.

Second GPU (NVIDIA, $126, personal purchase) is confirmed working and carrying Aven-2's active training. The AMD RX 5500 XT that trained Aven-2 through Days 1–15 is no longer in the setup.
