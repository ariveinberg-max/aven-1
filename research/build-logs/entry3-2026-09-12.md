# Build log — Entry 3

## Aven-2's first full capability-suite evaluation
Ran `evaluate_capabilities.py` against Aven-2 (153M) for the first time this session — 0/30 across all five categories. This is the expected, honest result for a pretrain-only checkpoint with zero instruction fine-tuning; it has never seen the `### Instruction:` format at all. Not comparable to Aven-1's own 0/30 score, which has a completely different cause (documented separately).

Getting this eval to run at all surfaced a real bug: cross-machine checkpoint loading was broken by a torch-version difference between machines — newer `weights_only=True` loading rejected specific numpy objects needed to deserialize this project's own saved RNG state. Fixed with a targeted, documented safe-globals allowlist (PyTorch's own recommended remediation for exactly this situation), not by disabling the safety check.

## A real production incident: Aven-2 training fully stopped
The same class of bug, in a different environment (the isolated DirectML venv, an older pinned torch for AMD GPU support), turned out to have already crash-looped Aven-2's actual training process through its full 20-retry budget and stopped it entirely — silently, with no one watching, roughly an hour before it was caught by coincidence while running the eval sweep above.

Fixed properly: extracted a shared `allow_safe_rng_globals()` helper covering the fuller set of globals this checkpoint format needs across different torch builds, verified locally (115/115 tests), deployed, and manually restarted training. Confirmed genuinely recovered — not just "no longer erroring" — by watching real step progress resume (step 11,260 → 11,300+, perplexity continuing to decline) and real CPU usage on the training process.

## One honest loose end
Two separate runs reported different parameter counts for what should be the identical Aven-2 architecture: 153,450,496 (the eval run) vs. 155,547,648 (the live training log), same `--width 1024 --layers 12 --heads 16 --context 192`. Not yet explained. Logged clearly in `research/scoreboard.md` rather than silently picking one number to trust.
